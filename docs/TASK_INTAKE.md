# 助手录入任务

1. 确认用户使用的服务地址（协议、IP、端口），不能把测试服务器或另一个浏览器的 localStorage 当作目标。
2. 保留用户原任务标题。只询问会影响正确录入的缺失信息；未指定时用待处理、中优先级、无截止日期，不编造描述或负责人。
3. 使用页面或同源 API 读取服务器现有任务，检查是否已经录入，避免重复。
4. 通过页面提交或向 API 发送带 revision 的修改。批量导入先预览并确认冲突；不直接手工编辑运行中的 tasks.json。
5. 409 时重新读取并核对，不无条件用新 revision 重试覆盖。网络失败时先核对是否已保存再重试。
6. 保存后重新读取服务器，核对标题与状态，再向用户报告。其他浏览器刷新可见。

上述流程不授权提交 Git、部署服务器、执行清单中的工作或创建 Codex 子任务。当前全局 Skill 未自动更新。

## 使用 AI JSON 追加任务

打开设置 → 粘贴 JSON → 预览追加结果 → 确认导入。也可以继续选择 JSON 文件。两种入口使用相同的服务器校验、ID 去重与 revision 冲突检查，只追加新任务，不替换整个看板。

最简输入（仅为格式示例，不代表自动录入）：

```json
[
  {"id":"ai-blog-001","title":"整理自媒体学习笔记"},
  {"id":"ai-english-001","title":"修复英语项目句子","pri":"high"}
]
```

- `id`、`title` 必填。ID 只使用字母、数字、短横线、下划线，不超过 100 字符；标题不超过 100 字符。每项使用不同 ID，同一任务重复导入时保持原 ID。
- 可选字段：`desc`（最多 500 字符）、`pri`（high/medium/low）、`st`（todo/doing/review/done）、`tag`（最多 18 字符）、`due`（YYYY-MM-DD）；未指定时使用默认值，不编造任务要求。
- 同 ID 同内容跳过；同 ID 不同内容阻止整批导入，不会覆盖。若是编辑已有任务，应使用看板编辑功能；不要通过改 ID 将同一任务误录为新任务。同标题但不同 ID 不会自动去重。
- 请 AI 只输出合法 JSON 数组，不要注释或 Markdown 代码围栏。完整的 Taskleaf 导出文档仍兼容。
- 预览和取消不修改服务器；修改粘贴内容后需要重新预览。网络错误或 409 时保留输入，重新预览并核对后再确认；刷新页面会丢失未保存草稿。
